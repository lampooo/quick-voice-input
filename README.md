# 快捷语音输入

一个 Mac 菜单栏小工具：在任意输入框里**长按鼠标左键**（默认 0.5 秒）就开始用微信输入法、豆包输入法或网易叭哥说语音输入，说完**松开鼠标**，文字上屏。

它自己不做语音识别。微信输入法、豆包输入法是「按住说话」：长按时，它替你按住语音快捷键，松开时再替你松开。网易叭哥说是「点按一次开始、再点按一次结束」：长按时，它替你点按一次它的语音快捷键，松开鼠标时再点按一次（做法和防卡保护见下面「网易叭哥说」一节）。

## 工作原理

1. 左键按下后开始计时。0.5 秒内松开或移动超过约 5 pt，就当成普通点击或拖选，不做任何干预。
2. 时间到时，用「辅助功能」接口判断指针下是不是可编辑的输入框（密码框不触发）。
3. 是输入框的话，先补发一个 mouseUp，让应用结束「按住鼠标」状态；再决定用哪个语音输入法，当前不是它就切过去（网易叭哥说是独立 App，不切换）；然后按住它的语音快捷键，或者对点按切换的引擎点按一次。
4. 说话期间，拖动鼠标会被改成普通移动，不会选中文字。
5. 松开鼠标时，这次 mouseUp 会被吞掉，同时松开快捷键（点按切换的引擎则再点按一次），输入法识别整理后上屏。
6. 松开后 5 秒内，比较输入框的字数，把「有没有上屏」写进日志（只看字数，不读取内容）。

另有两层保护：一是定时核对鼠标的真实状态，二是退出时一定松开按键，避免修饰键卡住。

## 系统要求

- macOS 13 或更新版本
- 至少装一个语音输入法或语音输入 App：
  - 微信输入法 Mac 版 2.2.1 或更新版本（2.2.1 起可以自定义语音快捷键；开发机上是 2.2.3）
  - 豆包输入法 Mac 版（开发机上是 1.0.0）
  - 网易叭哥说 Mac 版（独立 App，不是输入法；开发机上是 1.0.35）
- 自己编译需要 Xcode 16（Swift 5.9 及以上）

## 安装

```bash
git clone <仓库地址> quick-voice-input
cd quick-voice-input
./scripts/install.sh          # 编译、打包、签名并安装到 ~/Applications，不会自动启动
./scripts/install.sh --open   # 安装后立即打开
```

安装位置是 `~/Applications/快捷语音输入.app`。它是菜单栏应用，没有 Dock 图标。

签名方式：打包脚本会自动使用钥匙串里的「Apple Development」或「Developer ID」证书，这样以后重新打包也不用重新授权。找不到证书时退回 ad-hoc 签名，这种情况下每次重新安装都要重新授权。需要指定证书时，可以设置 `SIGN_IDENTITY="证书名称"`。

Bundle ID：「辅助功能」授权和设置都跟着 Bundle ID 走，所以打包时会沿用 `~/Applications` 里已安装版本的 Bundle ID；第一次安装时用 `com.quickvoiceinput.app`。需要指定时，可以设置 `BUNDLE_ID=你的.bundle.id`。

## 第一次使用

打开后会自动弹出设置向导（窗口打开期间，Dock 里会临时出现它的图标）：

1. **授权「辅助功能」**：点「去授权」，在「系统设置 → 隐私与安全性 → 辅助功能」里打开「快捷语音输入」。
2. **选择语音输入法**：默认「自动（跟随当前输入法）」。向导会列出微信输入法、豆包输入法和网易叭哥说的安装情况，以及它们各自的语音快捷键。
3. **确认语音快捷键**：每个引擎默认「跟随」它自己的语音快捷键设置，长按时按住（叭哥说：点按）同样的键，一般不用改。装了多个时，用顶部的切换按钮分别查看。
4. **测试**：点「开始测试…的语音快捷键」，大约 20 秒跑完，会告诉你哪个键可用。网易叭哥说的测试会让它真的开始录音约 1.5 秒再结束。然后在「试一试」的测试框里长按试一次，下面会显示这次有没有上屏。

### 语音输入法怎么选

- **自动（默认）**：当前输入法是微信输入法或豆包输入法时，就用它。是其它输入法（比如 ABC）时，用最近用过的那个；开着「触发前自动切换输入法」的话，会先切过去。
- **微信输入法 / 豆包输入法**：总是用选定的那个，当前不是它就先切过去。
- **网易叭哥说**：独立 App，没有输入源，不需要也不会切换输入法，在任何输入法下都响应。「自动」不会去选它（除非微信输入法和豆包输入法都没装），要用它请在「语音输入法」里明确选「网易叭哥说」。

### 快捷键怎么选

- **跟随输入法（默认）**：直接用输入法里设置的「按住说话」快捷键。以后在输入法里改键，下一次长按就会跟着变，不用重启：每次长按都会重新读取输入法的设置文件。
- **手动指定**：可以选预设（微信输入法、豆包输入法：右 Option、右 Command、右 Control、右 Shift、⌥ + 空格；网易叭哥说：左侧 ⌃⌘ + L、左侧 ⌃⌥ + V、左 Command、左 Option），也可以点「录制快捷键…」录入任意组合，比如左 Option + 空格。要和输入法里的设置保持一致。
- 快捷键里带普通键（比如空格）时，界面会提示风险：如果输入法没有拦截这个键，可能会在输入框里打出字符（⌥ + 空格会打出不换行空格），或者触发系统快捷键（⌃ + 空格是切换输入法）。网易叭哥说会拦下它绑定的整个组合，所以只提示系统快捷键；为保险，叭哥说没在运行、或这个组合不是它设置里的键时，本应用不点按。
- 快捷键和输入法自己的设置冲突时也会提示：它同时是输入法「按一次开始说话」的键；输入法开了「用左右 Command 选候选词」；豆包开了「全局唤起语音」且用了同一个键。
- 以下情况跟随不了，这时会暂时改用手动指定的键，并在界面上说明原因：语音快捷键还是默认的 Fn（macOS 不允许程序模拟 Fn；叭哥说默认就是 Fn）、快捷键被清空或关闭、设成了连按快捷键、叭哥说用了鼠标键。叭哥说手动指定的键带字母时（比如推荐的 ⌃⌘ + L），在叭哥说里设好之前不点按，免得字母漏进输入框。

推荐的设置：

| 输入法 | 「按住说话」改成 | 在哪里改 |
| --- | --- | --- |
| 微信输入法 | 右 Option（⌥） | 微信输入法设置 → 语音 →「按住说话」 |
| 豆包输入法 | 右 Command（⌘） | 豆包输入法设置 →「语音快捷键设置」→「按住说话，松手结束」 |
| 网易叭哥说（「语音输入」，点按切换） | 左侧 ⌃⌘ + L（左 Control + 左 Command + L；叭哥说最多录 3 个键）；单独的左 Command 也可以 | 网易叭哥说设置 →「快捷键」→「语音输入」；设置在 `~/Library/Application Support/com.bageshuo/bageshuo-store.json` |

这几个键程序都能模拟。微信输入法、豆包输入法的键单独按也不会打出字符；叭哥说的组合里的 L 由叭哥说自己拦下。豆包默认把右 Option 用作「按一次开始说话」，所以豆包不要用右 Option；右 Shift 会切换输入法的中英文，也不建议用。叭哥说不要用右 Option、右 Command：它在任何输入法下都监听，会和微信输入法、豆包输入法同时响应。调研细节见 [docs/wetype-spike.md](docs/wetype-spike.md)、[docs/doubao-spike.md](docs/doubao-spike.md)、[docs/bageshuo-spike.md](docs/bageshuo-spike.md)，叭哥说推荐键的核对记录见 [docs/bageshuo-hotkey.md](docs/bageshuo-hotkey.md)。

## 网易叭哥说（点按开始 / 点按结束）

网易叭哥说是独立 App，它的「语音输入」快捷键（设置 →「快捷键」）是**点按一次开始、再点按一次结束**，不是按住。本应用的做法：

1. 长按到时间后，先补发 mouseUp（鼠标按键在目标应用里已经结束），再把它的快捷键**完整点按一次**（按下、约 0.1 秒、松开）开始录音。
2. 用 CoreAudio 看默认输入设备的 `kAudioDevicePropertyDeviceIsRunningSomewhere`（不需要麦克风权限），**确认麦克风真的开始了**才算开始。
3. 松开鼠标时，再点按一次结束，然后确认麦克风真的停了。

快捷键默认跟随叭哥说自己的设置：单个修饰键（左 Command、左 Option…）就点按这个键；组合（比如推荐的 ⌃⌘ + L）就按下、松开整个组合，按下期间不会自动重复。修饰键总是按 ⌃、⌥、⇧、⌘ 的顺序按下、反过来松开，所以 Command 最后按下、最先松开，不会单独按着。在叭哥说里改键后，下一次长按就会跟着变。只有「语音输入」还是默认的 Fn、或设成了鼠标键时才跟随不了（程序无法模拟），这时暂时点按手动指定的单个修饰键；手动指定的是带字母的组合时不点按。

### 推荐的快捷键：左侧 ⌃⌘ + L

叭哥说的录制框最多录 3 个键。在叭哥说「设置 → 快捷键」里点「语音输入」的框，按住**左侧**的 Control 和 Command，再按 L。叭哥说区分左右，要用左侧的修饰键。理由：

- 点按切换用组合键最稳：点按一次就是一次完整的按键，叭哥说按「修饰键集合正好相等 + 按下了这个字母」来认，合成起来比单独点按一个修饰键确定。
- 右 Option、右 Command 已经是微信输入法、豆包输入法的语音键，叭哥说在任何输入法下都监听，会同时响应；这个组合和它们没有共同的修饰键。
- 不会变成 Command + 点击，也不会被当成选候选词：先结束鼠标点击再点按，Command 最后按下、最先松开；点按期间真的又点了鼠标，本应用会把合成的修饰键从这次点击上去掉。
- 字母 L 不会打进输入框：叭哥说在 HID 层拦下它绑定的键。「终端」的「清除屏幕」也是 ⌃⌘L，同样被叭哥说拦下；本应用只在叭哥说正在运行、并且它设置里的键就是这个组合时才点按。

**单独的左 Command 也可以用**，不是非改不可：单独一个修饰键什么都打不出来。要注意的是输入法开着「用左右 Command 选候选词」、屏幕上正好有候选词时，这次点按会被当成选词（设置向导会提示）。不想用带 Command 的组合，可以用左侧 ⌃⌥ + V。

开发机上核对过：系统快捷键（`com.apple.symbolichotkeys`）没有 ⌃⌘L；正在运行的 60 个有菜单栏的软件里只有终端用到；能拦截按键的全局监听只有微信输入法和叭哥说；叭哥说的热键监听不看按键来自哪个进程，会接受合成的按键。用 Carbon 注册的全局热键查不出来，合成后是否被拦下也要实测。详见 [docs/bageshuo-hotkey.md](docs/bageshuo-hotkey.md)。

### 防止录音卡住或误触发

点按切换最怕少发或多发一次，所以每一步都先确认再动手：

| 情况 | 做法 |
| --- | --- |
| 开始前麦克风已经在录音（会议、录音软件，或叭哥说自己已经在录） | 不点按。多点一次可能把别人的录音停掉 |
| 开始前键盘上有按键或修饰键按着 | 最多等 0.5 秒，还按着就放弃，不点按，菜单里提示。系统报告按下已超过 10 秒的普通键不算：那是没收到松开的残留状态（遇到过蓝牙键盘让 A 键一直显示按下，真按 A 也清不掉），日志里记一行 `ignoring key code …` |
| 叭哥说没有在运行 | 不点按，菜单里提示。没人拦下组合里的字母，点按会把它打进输入框 |
| 要点按的组合不是叭哥说设置里的键（手动指定，或跟随不了） | 不点按，菜单里提示，原因同上 |
| 点按后 2 秒内麦克风没有开始 | **不发第二次点按**（第二次会变成开始录音）。之后 4 秒内如果它迟到地开始了，会在松开鼠标时或第 4 秒结束它 |
| 两次点按之间 | 至少隔 0.8 秒，不会被当成双击；松开得很快就等够 0.8 秒再点按 |
| 结束前麦克风其实已经停了（比如你在叭哥说里手动停了） | 不点按 |
| 结束点按后 2 秒内麦克风没停 | 只补发 **一次**，再没停就放弃，菜单栏图标变成三角感叹号并响一声，提示手动结束 |
| 点按后系统里还有修饰键按着 | 立刻补发一次松开，日志里记录 |
| 结束那一次点按时，你的真实键盘正按着键 | 最多等 4 秒让你松开，还按着就仍然点按（录音不能一直开着） |
| 退出、暂停、改键、改语音输入法、权限被收回、事件监听重建、改应用规则 | 如果麦克风还在录音，先结束它。退出时同步完成，最多等几秒 |
| 上一次运行被杀掉或崩溃，留下「录音可能还在进行」的标记 | 下次启动时（有辅助功能权限）确认麦克风，还在录就结束它 |
| 叭哥说的设置窗口、它自己的窗口里长按 | 从不触发，避免合成按键落到快捷键录制框里改掉它的设置 |

### 如果还是用左 Command

- **⌘C、⌘V 这类真实组合键**：本应用只在键盘上没有任何按键按着时才点按；叭哥说自己对「多按了别的键」的判断是把这次点按作废，不会因为你的 ⌘C 开始录音。
- **点按期间你又按了别的键**：点按只持续约 0.1 秒，点按后会确认修饰键已经松开，没松开就补发松开。
- **候选词**：微信输入法、豆包输入法开着「用左右 Command 选候选词」时，屏幕上有候选词的瞬间点按 Command 可能被当成选词，叭哥说收不到。设置向导和菜单会提示这个冲突。
- 点按时长可以调：`defaults write com.quickvoiceinput.app tapHoldMs -int 150`（30 到 400 毫秒，默认 100，重启后生效）。

## 日常使用

- 在输入框里按住左键不动，约 0.5 秒后开始说话，松开结束。用触控板时会轻震一下。
- 菜单栏图标：`mic` 表示待命，实心 `mic.fill` 表示正在听写，`mic.slash` 表示已暂停，三角感叹号表示缺少权限。
- 快速点击、双击、拖选、按住修饰键点击都和平时一样。

### 屏蔽的软件

有些软件里不需要长按语音，可以把它屏蔽：在这个软件里点菜单栏图标，选「在〈当前软件〉中屏蔽」；也可以在设置窗口的「屏蔽的软件」里，从正在运行的软件中选，或者到「应用程序」文件夹里选 .app。列表里的软件可以随时移除。

屏蔽就是按应用规则里的「不触发」，两处是同一份设置，按 Bundle ID 保存。被屏蔽的软件里长按时，快捷语音输入完全不干预：不读取它的界面信息，也不补发任何鼠标或按键事件。移除屏蔽后，软件回到它原来的默认规则。

### 按应用规则

输入框靠「辅助功能」识别，长按约 0.15 秒、点击已经生效后才开始判断。像微信这样完全不向「辅助功能」暴露界面的应用，会改看鼠标指针：指针是文本 I 形光标时才触发。浏览器、编辑器这类有辅助功能信息的应用不用这条规则，因为它们在任何可选中的文字上都会显示 I 形光标。

如果某个应用还是识别不准，打开那个应用后，在菜单栏里把它设成「任意位置都触发」就行，这时在该应用里任意位置长按都会开始语音输入。终端类应用（Terminal、iTerm2、Warp、kitty、Ghostty 等）默认就是「任意位置都触发」。

## 常见问题

**测试显示「没有反应」**
先确认菜单里这个输入法的「语音快捷键」和它的「按住说话」一致；选「跟随…」最省事。再看测试结果底部有没有「安全输入」提示：密码框，或终端的「安全键盘输入」，会让所有键盘监听失效。

**怎么知道文字有没有上屏**
松开后菜单里会显示「最近一次：已上屏 N 个字符」或「5 秒内输入框里没有新文字」，日志里对应一行 `commit check`，记录开始前和松开后几个时间点的字数。有些应用不提供输入框字数，这时显示「无法判断」。

**授权了还是不工作**
在「辅助功能」列表里选中「快捷语音输入」，点「−」删除，再在向导里点「去授权」重新添加。用 ad-hoc 签名重新打包后必须这样做一次。

**某个应用里长按没反应**
把这个应用设成「任意位置都触发」。Chrome 和 Electron 应用第一次长按时才开启辅助功能树，可能需要再试一次。

**Option 或 Command 键像是卡住了**
按一下对应的键（比如右 Option、右 Command，或叭哥说组合里的左 Control、左 Command）就能恢复。正常情况下，快捷语音输入会在松开鼠标、退出或检测到异常时自动松开按键。

**网易叭哥说一直在录音，停不下来**
菜单栏图标会变成三角感叹号并提示。在叭哥说里手动点按一次它的语音快捷键，或点它自己的结束按钮。原因可能是：叭哥说没在运行或没收到合成的按键（先在设置向导里「测试」一次）、你在点按的瞬间按着别的键，或有安全软件拦截了合成按键。

**长按后叭哥说没反应**
菜单里会有一行提示。常见原因：麦克风被其它应用占用（本应用不去触发，免得把别人的录音停掉）、键盘上有按键没松开、叭哥说的快捷键在它的设置里被改了（下次长按会跟着变）、叭哥说没有开辅助功能权限、或它的快捷键是 Fn 或鼠标键（程序无法模拟，要在叭哥说里改成推荐的左侧 ⌃⌘ + L）。叭哥说没在运行，或这里的键和叭哥说设置里的不一致时，本应用不点按，菜单里也会写明。

设置向导里「测试语音快捷键」显示「测试没有得到结果」时，说明这次测试被跳过了（比如键盘上有按键没松开、测试被取消），不代表快捷键有问题，不用因此改快捷键，排除原因后再测一次就行。

**终端里上屏异常**
有用户反馈微信输入法 2.2.3 在终端里语音上屏异常，这是输入法自身的问题。

**排查信息**
在终端运行下面的命令，可以打印权限、每个语音输入法的设置和事件监听、快捷键和麦克风的状态（只读，不会按任何键）：

```bash
~/Applications/快捷语音输入.app/Contents/MacOS/QuickVoice --self-check
```

日志在 `~/Library/Logs/QuickVoiceInput/quickvoice.log`，只记录应用名、控件类型、耗时和输入框字数，不记录输入内容。

## 开发

```bash
swift build              # 编译
swift test               # 运行 QuickVoiceCore 的单元测试
./scripts/build-app.sh   # 打包到 build/快捷语音输入.app（UNIVERSAL=1 同时编译 Intel 版）
.build/debug/QuickVoice --render-setup /tmp/setup   # 仅 Debug 构建：离屏渲染设置向导截图，不显示窗口
```

| 路径 | 内容 |
| --- | --- |
| `Sources/QuickVoiceCore/` | 纯逻辑，可以单测：长按状态机、快捷键和按键序列、快捷键录制与风险提示、按应用规则、上屏判断 |
| `Sources/QuickVoiceCore/VoiceIME.swift` | 语音引擎的描述（微信输入法、豆包输入法、网易叭哥说；按住或点按、输入法或独立 App）、「自动」的选择规则、和其它引擎设置的冲突检查。支持新的引擎主要是在这里加一个描述 |
| `Sources/QuickVoiceCore/WeTypeSettings.swift`、`DoubaoSettings.swift`、`MMKVReader.swift`、`BageshuoSettings.swift` | 读取设置文件（微信、豆包是 MMKV，豆包的值是 NSKeyedArchiver 归档；叭哥说是 JSON，只取快捷键，不读账号和历史） |
| `Sources/QuickVoiceCore/TapToggle.swift` | 点按开始、点按结束的引擎：先确认再点按、最小间隔、补发一次、迟到的开始、崩溃恢复；通过注入的环境单测 |
| `Sources/QuickVoice/IMEInspector.swift` | 每个输入法的安装、输入源和快捷键状态；每次都按文件内容重新读取设置 |
| `Sources/QuickVoice/EventTap.swift` | 独立线程上的 CGEventTap，只监听左键，负责吞掉或改写事件 |
| `Sources/QuickVoice/TextFieldProbe.swift` | 用「辅助功能」识别输入框（从不查询本 App 自己），为 Chromium / Electron 开启辅助功能树，没有辅助功能的应用看 I 形光标 |
| `Sources/QuickVoice/KeySynth.swift` | 在 HID 层合成按键；修饰键用 flagsChanged，并带上区分左右的设备位 |
| `Sources/QuickVoice/VoiceController.swift` | 选语音引擎、切输入法、按住和松开快捷键或点按开始/结束、防卡键看门狗、退出时同步结束录音 |
| `Sources/QuickVoice/TapToggleSystem.swift` | 点按引擎用的真实环境：真实键盘是否空闲、CoreAudio 麦克风状态、修饰键残留检查、「录音可能还在进行」标记 |
| `Sources/QuickVoice/CommitChecker.swift` | 松开后比较输入框字数，判断有没有上屏 |
| `Sources/QuickVoice/HotkeyDiagnostics.swift` | 「测试语音快捷键」 |
| `Sources/QuickVoice/MenuBar.swift`、`Settings.swift`、`Onboarding.swift` | 菜单、设置、设置向导 |
| `scripts/` | 打包、签名、安装和图标生成 |

## 卸载

1. 在菜单里退出「快捷语音输入」。
2. 可选：清除设置和日志。要在删除 App 之前做，因为命令会从 App 里读出 Bundle ID：

   ```bash
   defaults delete "$(/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' ~/Applications/快捷语音输入.app/Contents/Info.plist)"
   rm -rf ~/Library/Logs/QuickVoiceInput
   ```

3. 删除 `~/Applications/快捷语音输入.app`。
4. 在「系统设置 → 隐私与安全性 → 辅助功能」里删除它；如果开了开机启动，也到「登录项」里删除。
